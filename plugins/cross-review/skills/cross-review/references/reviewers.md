# 리뷰어 선택과 실행

## 사전 상태 확인

- `command -v codex`, `command -v agy`로 설치 여부를 확인하고, 해당 CLI의 `--help`에서 현재 지원 옵션을 확인한다. 실행 파일명만으로 로그인 상태를 단정하지 않는다.
- Codex를 호스트로 사용하는 경우 현재 에이전트를 Codex 리뷰어로 사용한다. 별도 Codex CLI 호출은 필요하지 않다. 다른 호스트라면 Codex CLI 가용성과 `codex login status` 등 설치된 버전이 제공하는 인증 확인 명령을 확인한다.
- agy는 버전에 따라 auth/status 명령이 없을 수 있다. `agy models` 조회 성공은 조회 가능 상태로만 보고한다. 인증이 확인되지 않으면 `미확인`으로 표시한다. 토큰·쿠키·credential 파일을 열거나 출력하지 않는다.
- 인증 명령이 없어 실제 모델 요청으로 확인해야 한다면 비용과 외부 호출이 생긴다고 알리고 사용자가 연결 테스트를 요청하거나 Codex + agy를 선택한 뒤 수행한다. 프로젝트 밖 임시 작업 디렉터리에서 파일·도구 접근 없이 `OK`만 응답하도록 요청한다. 성공 시 해당 시점의 모델 호출 가능 상태로 보고한다. 로그인 갱신이나 설치는 자동 수행하지 않는다.

## 필수 선택

스킬을 호출할 때마다 대상 확인과 함께 `Codex only`와 `Codex + agy` 중 반드시 다시 선택받는다. 같은 세션이어도 이전 호출의 선택을 재사용하지 않는다. 선택은 해당 호출로 시작한 리뷰와 그 후속 대화·재개에만 적용한다. 사용 가능한 agy가 없으면 설치/인증 필요 상태를 설명하고 선택을 받는다. 실패를 숨겨 단독 모드로 전환하지 않는다.

Codex + agy 선택은 확인된 대상의 필요한 자료를 추가 서비스에 제공하는 범위를 포함함을 선택 안내에 명시한다. 관련 없는 파일·비밀은 보내지 않는다. 외부 전송 금지 정책이 있으면 이를 우회하지 않는다.

## 실행 자료와 권한

각 리뷰어에게 동일한 대상 경로, 분류·범위, HEAD와 변경 파일 상태, 관련 MD와 핵심 소스·테스트, read-only 제약, finding 형식을 준다. 결론이나 의심 버그를 전달하지 않는다. 파일 접근이 불가능한 리뷰어는 필요한 발췌와 줄 번호를 받으며 coverage 한계를 명시한다. CLI 실행 중 작업 트리가 변했으면 차이를 확인해 근거의 기준을 맞춘다.

- Codex CLI가 필요하면 `codex exec --help`를 확인하고 `--sandbox read-only`를 사용한다. 프롬프트 파일을 stdin으로 넘기고 별도 임시 파일로 결과를 받는다.
- agy는 `agy --help`를 확인하고 지원한다면 `--mode plan --sandbox`를 사용하며 소스·사양 변경 금지를 프롬프트에 명시한다. plan/sandbox가 완전한 읽기 전용 보장인지 단정하지 않는다. 프로젝트 쓰기를 막는 실행 환경이 없으면 임시 디렉터리의 필요한 자료 사본으로 실행하고 사본 밖 프로젝트 접근을 주지 않는다. 복사 범위를 확인하고 symlink가 원본 쓰기 접근을 허용하지 않게 한다.
- `--dangerously-skip-permissions`나 권한 우회 플래그를 사용하지 않는다. 권한 프롬프트 또는 미지원 기능 때문에 진행이 막히면 원인을 보고하고 필요한 선택을 받는다.
- shell 문자열에 프롬프트를 직접 보간하지 않는다. 구조화된 인자나 stdin/파일을 사용한다. 긴 리뷰는 비동기로 실행해 진행 상태를 알리며, 사용자가 지정한 제한 내에서 수행한다. 실패를 끝없이 재시도하지 않는다.

Codex only에서는 Codex 검토 결과를 제공한다. Codex + agy에서는 각각의 검토 후 근거를 재확인해 통합한다. 독립적으로 완료되지 않은 리뷰어를 참여 완료로 세지 않는다.
